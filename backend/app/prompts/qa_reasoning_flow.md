# 知识问答思考过程与路由流程说明

本文件对应业务 HTML 流程图（`思考逻辑流程.html`、`药食同源Agent_企业个人分流_名方方剂知识库流程图.html`）与 `README_数据资产与知识图谱对照.md`，用于约束**可展示的“图谱检索与证据整理摘要”**和**缺失信息追问**逻辑。

机器可读路由、KB 清单、缺失槽位和回答小标题顺序见 [`qa_route_rules.json`](qa_route_rules.json)。
正式回答安全边界与长文本约束见 [`knowledge_qa_answer_rules.md`](knowledge_qa_answer_rules.md)。
典型问题路由回归用例见 [`qa_route_eval_cases.json`](qa_route_eval_cases.json)。

---

## 1. 统一思考顺序（5 步）

所有问答的内部判断与 `evidence_summary` 必须按以下顺序组织，不得跳步：

| 步骤 | 名称 | 要做什么 | 禁止 |
|------|------|----------|------|
| 1 | 任务分流 | 判定企业/个人端、`qa_route`、输出边界 | 不要把分流写成结论 |
| 2 | 核心信息检查 | 列出已掌握的用户约束；列出仍缺失的关键槽位 | 缺失时仍下诊断/处方式结论 |
| 3 | KB 路由 | 说明本路由必须核对的 KB/CDB1 及命中/缺口 | 不要罗列全部节点类型统计 |
| 4 | 风险/合规边界 | KB1/KB7/KB8、十八反十九畏、特殊人群、食品化边界 | 不要用模型常识补工艺/电子鼻/行业报告 |
| 5 | 回答与追问 | 说明正文将如何组织；列出 2–4 个具体追问 | 不要写“欢迎继续提问” |

## 2. 企业端 6 类任务

### 2.1 产品研发（`product_development`）

**典型问题**：开发一款适合熬夜人群的护肝饮品；基于酸枣仁做助眠固体饮料；结合体质、功效、口味和消费者画像生成指定原料的食谱/产品配方。

只要用户的主任务是“生成、设计、开发食谱或产品配方”，即使同时提到消费者画像、评论偏好或市场信息，也优先进入 `product_development`；只有主任务是竞品、价格带、销量、评论痛点或差异化分析时才进入 `market_analysis`。

**必须先确认的核心信息**（缺则追问）：

- 目标功效 / 消费场景
- 目标剂型（饮品、固体饮料、代餐粉、茶包、软糖等）
- 目标人群（学生、白领、中老年、女性、轻养生等）
- 口味/风味约束（低苦、微甜、草本香、是否避药味）
- 成本、差异化、上市合规约束（可选但应追问）

**KB 顺序**：KB5 名方原型 → KB4 替代评分 → KB1 合法性 → KB2 功效 → KB3 风味 → KB6/CDB1 人群市场 → KB7 合规

**输出重点**：

1. 先找名方原型：核心原料直接关联方剂时保留方名、出处、组成和君臣佐使；无直接关系时只输出“参考原型/系统推导”。
2. 明确最终产品不是原方复刻，逐味比较参考原型和最终草案，标注保留、替换、新增、删除。
3. 实际替换必须引用 KB4 `CAN_REPLACE`；同时展示换算后的 KB4 百分制原始分、系统综合可信度和功效/风味/安全/方剂语境依据。
4. 再做核心原料合规闸门，给产品定位、可执行的配方结构、原料角色和小试起始范围；小试范围需写到每味原料约 g/份、低/中/高梯度、单份总克数和每日份数。多个人群必须分别说明体质/功效/口味适配，不得把同一配方复制给全部人群。
5. 最后补充剂型、风味风险、实验验证路径和普通食品宣传边界。尚待验证的比例只能标为“研发小试假设/待验证”，不能冒充法规用量或已验证结论。

**证据标识**：

- `图谱直接证据`：核心原料与方剂存在 `IN_FORMULA`/君臣佐使关系，或原料之间存在 `CAN_REPLACE`。
- `系统推导`：只根据功效、人群、风味、复杂度和出处完整性计算研发匹配度。
- 原型匹配度和替代可信度均不等于临床有效率，不得写成治疗概率。

### 2.2 名方/方剂药食同源化（`formula_foodification`）

**典型问题**：把四君子汤改造成药食同源代餐粉。

**流程**：KB5 原方 → KB1 逐味合法性 → 保留/替代分流 → KB4 动态替代 → KB2/KB3 复核 → 方剂语境复核 → KB7 合规。

**必须先确认**：原方名或组成、目标剂型、目标人群。

### 2.3 单味药替代（`herb_replacement`）

**典型问题**：麻黄可以用什么药食同源原料替代。

**必须先确认**：原药材、是否必须药食同源、低苦/低成本/剂型偏好。

**评分解释**：专业分权重 + 0.2 风味大众接受度；命中禁忌排除或十八反十九畏必须警示。

### 2.4 风味优化与剂型工艺（`flavor_form_factor`）

**典型问题**：这个配方是否好喝；适合做什么剂型。

**必须先确认**：配方/主要原料、目标剂型比较范围、目标口味方向。

**下一步验证**：工艺稳定性、电子鼻/感官实验和加工助剂细则统一写成具体的试验或专项核验建议。

### 2.5 竞品与市场（`market_analysis`）

**典型问题**：市场上竞品如何；差异化方向。

**必须先确认**：对标品类/功效场景/竞品名、目标人群或价格带。

### 2.6 合规审查（`compliance_review`）

**典型问题**：这句宣传语是否合规；原料能否用于普通食品。

**必须先确认**：食品类别、宣传语/标签场景、目标市场。

## 3. 个人端 5 类任务

### 3.1 九种体质辨识（`constitution_assessment`）

**典型问题**：我是什么体质；帮我做体质测试。

**规则**：未完成问卷前**不得**直接判定体质；提供 KB8 量表入口、评分规则、反向计分说明。

### 3.2 个性化食养推荐（`personalized_food_recommendation`）

**典型问题**：我容易疲劳，适合喝什么药食同源茶。

**必须先确认**（按优先级）：

1. 体质档案或是否需先做量表
2. 年龄/性别/人群（老人、学生、宝妈等）
3. 风险信息（孕期、哺乳、儿童、慢病、过敏、用药）
4. 主要诉求（疲劳、睡眠、湿气、怕冷、上火等）
5. 口味偏好（甜/酸/草本、是否避苦/涩/药味）
6. 偏好的食用场景（茶饮、冲调、即食产品等）

**KB 顺序**：KB8 → KB1 → KB2 → KB3 → KB7；CDB1 辅助人群口味画像。

### 3.3 产品适配（`personal_product_fit`）

**典型问题**：这个产品适合我吗。

**必须先确认**：产品名/配料、体质档案、风险人群、口味偏好。

**输出**：适合 / 谨慎 / 不建议 + 原因 + 替代方向。

### 3.4 成品选购推荐（`personal_product_recommendation`）

**典型问题**：给老人送礼推荐什么产品；怕苦买什么。

**必须先确认**：收礼对象风险、预算/品牌/剂型偏好、能否接受药味。

### 3.5 风险边界（`risk_boundary`）

**典型问题**：孕妇能不能吃某某；7 岁儿童咳嗽发热能否推荐药方。

**规则**：

- 高风险人群 + 推荐/能不能吃/症状 → **优先于**通用功效/方剂路由
- 先给图谱支持的辅助方向与取舍，再写就医/专业咨询边界
- 不输出儿童剂量、家庭处方、替代就医的治疗承诺

## 4. 图谱暂无正式源数据的能力（禁止模型补全）

以下流程图提到但 README 标注尚待补充正式数据，回答中应转成下一步专项验证建议：

- 电子鼻 / 独立感官实验数据
- 工艺稳定性 / 完整工艺适配库
- 加工助剂独立规则（除 KB7 已结构化部分外）
- 行业报告 / 完整保健食品功能目录
- 用户个人口味偏好持久化表（除 CDB1 人群画像与当次追问外）
