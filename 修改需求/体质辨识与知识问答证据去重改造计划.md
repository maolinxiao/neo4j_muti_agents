# 体质辨识与知识问答证据去重改造计划

## 1. 背景问题

当前知识问答中存在三类重复展示：

- 正式回答里的【图谱依据】
- 折叠区里的“图谱证据摘要”
- 可视化区域里的“证据子图”

这三块都在解释图谱命中结果，导致用户看到的信息重复、层次不清。同时，正式回答各模块之间逻辑联系不够强，【核心结论】有时只是在复述“命中了哪些实体”，对用户没有直接价值。

体质相关问题目前主要通过知识问答临时输出量表文本，缺少可交互、可保存、可独立管理的体质辨识功能。

## 2. 改造目标

1. 正式回答减少证据重复，只保留对用户有用的判断和建议。
2. “图谱证据摘要”负责展示检索过程、关键实体、证据缺口。
3. “证据子图”只负责图谱可视化核验。
4. 体质量表改为表格和交互组件，不再把大量题目塞进正文。
5. 用户可以直接选择已知体质，也可以点击测试逐题作答。
6. 测试完成后保存用户体质档案，后续知识问答自动带入。
7. 左侧工作台新增“体质辨识”入口，支持独立管理体质档案和历史测评。

## 3. 问答结构调整

### 3.1 三类证据展示重新分工

正式回答：

- 只写业务判断、解释和建议。
- 不写节点数、关系数、关系类型名。
- 不重复“图谱证据摘要”的原句。

图谱证据摘要：

- 写命中了哪些 KB。
- 写关键实体和关键关系。
- 写证据缺口和边界。
- 作为折叠区展示。

证据子图：

- 展示节点、关系、主路径。
- 供用户点击核验。
- 不承担正文解释职责。

### 3.2 正式回答小标题调整

减少通用【图谱依据】，改成更贴近业务的小标题：

| 问题类型 | 建议小标题 |
|---|---|
| 体质问题 | 【量表依据】或【判断依据】 |
| 产品问题 | 【推荐理由】 |
| 方剂问题 | 【原方依据】、【替代依据】 |
| 合规问题 | 【合规依据】 |
| 药材功效问题 | 【知识依据】 |

### 3.3 【核心结论】规则

【核心结论】必须直接回答用户问题，不能写成检索事实。

不推荐：

```text
本次问题命中了这些图谱实体：黄精、气虚质、补气。
```

推荐：

```text
现在还不能直接判断你的体质，因为需要先完成体质量表。你可以先选择已知体质；如果不确定，可以点击“开始体质测试”。
```

## 4. 体质问答交互方案

当用户在“知识问答”中问到：

- 我是什么体质
- 我不确定自己的体质
- 帮我做体质测试
- 我适合吃什么
- 这个产品适合我吗

系统应判断是否已有体质档案。

### 4.1 用户已有体质档案

回答中直接引用已保存体质：

- 体质类型
- 来源：手动选择 / 量表测评
- 最近更新时间
- 结合 KB8、KB1、KB7 给出食养、产品适配和风险边界

### 4.2 用户没有体质档案

回答中给出简短说明，并展示体质交互卡片：

- 九种体质表格
- “我已知道自己的体质”选择区
- “不确定，开始测试”按钮
- 逐题作答区域
- 保存体质档案按钮

### 4.3 体质类型表格字段

| 字段 | 来源 |
|---|---|
| 体质名称 | `ConstitutionType.constitution_type_name` |
| 体质分类 | `constitution_category` |
| 简要说明 | 图谱属性 |
| 食养方向 | KB8 体质食养方向 |
| 慎用原料 | KB8 体质慎用原料 |
| 操作 | 选择为我的体质 |

### 4.4 体质量表字段

| 字段 | 来源 |
|---|---|
| 题号 | `ConstitutionQuestion.question_code` / `question_no` |
| 题目 | `question_text` |
| 体质归属 | `constitution_type_name` |
| 是否反向计分 | `reverse_scored` |
| 评分选项 | `score_1` 到 `score_5` |

评分控件固定为：

```text
1 从不 / 2 很少 / 3 有时 / 4 经常 / 5 总是
```

## 5. 后端改造计划

- `primary_constitution`
- `secondary_constitutions`
- `result_summary`

- `updated_at`

### 5.2 新增 Schema

建议新增：

- `backend/app/schemas/constitution.py`

包含：

- `ConstitutionTypeRead`
- `ConstitutionQuestionRead`
- `ConstitutionProfileRead`
- `ConstitutionProfileUpdate`
- `ConstitutionAssessmentCreate`
- `ConstitutionAssessmentRead`

- `list_constitution_types()`

### 5.4 新增 Service

建议新增：

- `backend/app/services/constitution_service.py`

职责：

- 从 Neo4j 读取九种体质和问卷。

- 生成结果摘要。
- 保存体质档案。

### 5.5 新增 API

新增 router：

- `constitution_router = APIRouter(prefix="/constitution", tags=["constitution"])`

接口：

- `GET /constitution/types`
- `GET /constitution/questionnaire`
- `GET /constitution/profile`
- `PUT /constitution/profile`
- `POST /constitution/assessments`

## 6. QA 编排接入计划

### 6.1 上下文接入

`QAOrchestrator` 构建上下文时读取当前用户体质档案。

注意：当前 `ask()` / `ask_stream()` 只接收 `session_id` 和 `question`，如果要按登录用户保存体质，需要从路由层把 `current_user` 传入，或通过 session 关联用户。

### 6.2 问答行为

如果用户已有体质档案：

- 将体质写入 LLM context。
- 回答中直接结合该体质给食养、产品适配、风险边界。

如果用户没有体质档案：

- 回答正文只说明“需要先选择或测试体质”。
- 在 `extra_payload.constitution_assessment` 中返回体质交互组件数据。

建议 `extra_payload` 结构：

```json
{
  "constitution_assessment": {
    "mode": "need_user_choice",
    "types": [],
    "questions": [],
    "score_options": [],
    "existing_profile": null
  }
}
```


### 7.4 独立体质辨识页面布局

页面结构：

- 顶部：当前体质档案卡片
- 左侧：九种体质表格
- 右侧：测试进度和当前题目
- 下方：历史测评记录

核心操作：

- 选择体质
- 开始测试
- 上一题 / 下一题
- 保存结果
- 重新测评
- 查看历史记录

### 7.5 知识问答中嵌入体质组件

`ChatView.vue` 中检测：

```js
msg.extra_payload?.constitution_assessment
```

如果存在，渲染 `ConstitutionAssessmentPanel`。

这样正文保持简洁，体质量表由组件承载。

## 8. 验收问题

知识问答：

- 我是什么体质
- 我不确定自己的体质，帮我测试
- 我是气虚质，适合吃黄精吗
- 这个产品适合痰湿质吗
- 孕妇能不能吃某某原料

独立页面：

- 可以查看九种体质表格。
- 可以手动选择体质并保存。
- 可以逐题完成体质测试。
- 可以自动计算主体质和兼夹体质。
- 可以查看历史测评。
- 保存后回到知识问答，系统能自动带入该体质。

## 9. 建议实施顺序

1. 调整 QA 回答模板，减少【图谱依据】与证据摘要重复。
2. 修改体质问答输出，让正文只提示“可选择 / 可测试”，量表放入 `extra_payload`。
3. 新增后端 `/constitution` 接口和 PostgreSQL 模型。
4. 新增 `ConstitutionAssessmentPanel.vue`，先在 `ChatView.vue` 中嵌入。
5. 新增独立 `ConstitutionView.vue` 工作台页面。
6. 将保存后的体质档案接入 `QAOrchestrator` 上下文。
7. 运行后端 `py_compile`。
8. 运行前端 `npm run build`。
9. 用验收问题逐项测试。

## 10. 关键原则

- 正文回答讲判断，不讲检索流水账。
- 图谱摘要讲证据，不复述正文。
- 证据子图做核验，不承担正文解释。
- 体质量表做成交互组件，不塞进大段文本。
- 体质结果可以保存，后续问答自动使用。
- 体质辨识是辅助判断，不替代临床诊断。
